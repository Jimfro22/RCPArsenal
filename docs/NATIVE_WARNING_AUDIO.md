# Optional native warning sound - 0.15.3-alpha.4

Owner choice: visual at the saved threshold; sound from Blizzard's native low-health warning, normally 35%. This is separate from a 60% visual setting. The native warning's settings and UI semantics apply; this proxy does not guarantee an exact health-only event in every client. No copyrighted clips, custom assets or broad sound library.

Personal Tools > Reminder text & sound contains Low-health sound and Preview sound. The audio preference defaults ON when unset; the reminder master remains OFF for fresh profiles. Saved audio OFF, visual thresholds, text, sizes, positions, profiles and other tools are preserved. Automatic sound follows Both / In combat / Out of combat and requires a definitely alive player. Preview explicitly requests only the built-in alert, changes no preference/latch and needs no health or bags. Native/game volume settings can mute playback.

## Guarded event-driven integration

Independently authored NativeWarningAudio.lua binds only additive LowHealthFrame OnShow/OnHide hooks. Both documented HookScript boolean returns must be public true before activation; partial failures remain inert. Each script is attempted once per native frame. Parent callbacks are also required. Hook setup follows explicit master/audio opt-in independently of the combat playback mode, so an In-combat-only profile binds before combat. Missing bindings/frame can retry only on explicit enable or world entry, never on health events or a timer. Existing successful hooks are reused. No Blizzard script replacement, visibility/parent/security/CVar/threshold mutation or invocation of privileged health mixins.

Every observation guards IsShown and IsVisible with pcall, issecretvalue and exact boolean validation. Playback also requires public allowed reminder policy, an enabled native warning CVar, no fullscreen panel, visible UIParent, and no shown cinematic/movie when present. Unknown/secret/error states suppress audio. Disabled hooks return before native frame/CVar/panel work. Cached UI status reads no native state. Sound never reads health, alpha, the Arsenal curve, inventory, talents or another player's data.

The latch waits for an eligible readable own-shown=false observation, then permits one subsequent eligible shown episode. Initial already-shown state, duplicate hooks, suppressed states, profile/mode changes and parent restoration cannot produce catch-up playback. Ancestor OnHide with own-shown=true never counts as clear. The latch is consumed before playback, including failed/muted playback; preview and appearance/text/threshold edits do not rearm it. Eligibility transitions are detected inside native callbacks too, rather than relying on native/addon event-handler ordering.

Native world bootstrap and parent/CVar transitions stay disarmed rather than arming from a potentially stale pre-update clear state. Opted-in hooks bind before combat; playback/arming waits for the first world-entry lifecycle. This conservative behavior can skip a warning until a genuine readable clear has been observed; no delayed recheck/polling fallback is added. Public option/profile/world/life/combat events and UI.TopLevelParentShown/Hidden provide bounded reconciliation.

Use SOUNDKIT.ALARM_CLOCK_WARNING_3 (12889), the built-in stopwatch countdown alert, with default PlaySound parameters. No forced channel/volume, timer, retry or assumed duration. Automatic alerts and manual previews track separate ordinary returned handles. Only the automatic handle is stopped on warning clear, disable or automatic ineligibility; incidental automatic callbacks never stop a manual preview. A new preview stops only its own prior preview. Other addons' and Blizzard's sound handles are never selected.
