## Quiet first run and profile contract

The DEFAULTS table at `Core.lua:27` enables `shown`, `autoShowEncounter`, `demoMode`, scan strip/demo preview, Quick Bar, several categories, and callout controls. `CopyDefaults` runs before migration during `ADDON_LOADED` (`Core.lua:729`). Old migration steps re-enable shown state, preview, Quick Bar, and actions; normalization also supplies true defaults. Changing only DEFAULTS would miss those paths.

Recommend one final schema-18 migration that records a one-time hub opt-in transition, sets optional modules/actions off for fresh and older profiles, and preserves visual values, positions, templates, ignored groups, and content choices. Do not reset the whole profile. Once the player enables a module in schema 18, later login and normalization must preserve that choice. Review this upgrade behavior with the owner; existing settings cannot prove which old true flags were deliberate consent.

`ProfileIO.lua:131–207` exports explicit fields with several true-default fallbacks; imports start from `CreateDefaultProfile`, apply fields, normalize, then call `ApplyImportedProfile`. That last function keeps local `shown` and HUD/puck positions, but imports Quick Bar enablement and other behavior. Recommend keeping feature enablement local for hub-era imports, while copying portable presentation/content settings. Otherwise an imported team profile can switch modules on implicitly. Provide a deliberate apply step for any future import that changes behavior. Add explicit schema/format compatibility handling while retaining RCPA11/RCPA9/RA8 readers.

Meaningful offline profile tests should cover no DB, schema 0/5/8/10/12/17, partially missing tables, reset, repeat login, on/off persistence, old exports, and import without moving anchors or silently enabling optional modules. In-game checks must also cover encounter auto-show and secure action state. Inspection currently schedules work on login, world, roster, and ready-check events even with the HUD hidden (`Inspect.lua:1439–1549`); decide whether optional inspection should also sleep until a capability/leader feature needs it. Recommended: gate scheduled scanning on an enabled consumer, while allowing an explicit scan request.

## Early API and integration risks

Dedicated API research now identifies Retail 12.1.5 build 70448 as the source baseline and supports readable item-based selection with a secret health display curve passed directly to `SetAlpha`. Do not branch on health in Lua. A constant child animation can continue while the parent alpha hides it. Inclusive threshold equality and actual raid item returns remain client tests. Use the completed API report and combat probe for this spike rather than repeating source research. [Unit API source](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua)

`C_Item.GetItemCount`, `C_Item.IsUsableItem`, and `C_Item.GetItemCooldown` are candidate availability APIs. The generated documentation lists a boolean cooldown-enable return; do not assume the old numeric API shape. Confirm charges, shared potion restrictions, combat lockouts, temporary bag locks, item data loading, and relevant item IDs. Test only data availability/secret status in restricted contexts, not logging secret values. [Item API source](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua)

No NSRT or new feature integration exists in this baseline. Public NSAPI profile entry points are a stronger boundary than internal note/position functions; isolate both and maintain tested versions. NSRT remains installed from its own distribution. The dedicated API research pins EasyAutoAcceptRes at `b902c0d7b5d961ef12110db24410d8c50e5fd3eb`, including its MIT notice, and finds no new documented blocker for normal resurrection. Keep battle res manual and retain the notice if adapting code. [Reference source](https://github.com/JoesphG/EasyAutoAcceptRes/blob/main/AutoAcceptRes.lua), [license](https://github.com/JoesphG/EasyAutoAcceptRes/blob/main/LICENSE)

Existing runtime risks remain cold-login textures, real subgroup operations, changed-side whisper delivery, local countdown state when another player starts/cancels a countdown, profile migrations, and stale help text. Source verification and packaging checks do not close these. Preserve the capability ownership wording and composition-only coverage meaning. New receivers do not bypass Blizzard encounter communication limits.
