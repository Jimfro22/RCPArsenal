# Marker center release and activity synchronization (alpha.24)

With the optional wheel enabled, center release places the next configured marker at the cursor, before or after the visual appears. Sector release still opens Blizzard's ground reticle and requires the actual left-click on terrain. Right-click/Escape cancels the wheel before release or native targeting afterward. Wheel OFF retains down-phase instant cursor placement. Existing Place/Clear keybinding identities and saved order remain unchanged.

The center/sector boundary is now circular, at the visible sectors' inner edge: radius 71 UI units plus a 0.01-unit numeric tolerance for scaling/normalized-coordinate arithmetic. Secure input and visuals use the same boundary. A 26–30 unit quick-tap movement previously selected an invisible sector under the old 22-unit square threshold; it now remains center. This reproduces an accidental-reticle path, **not** the owner's estimated every-third native cadence. The secure handler stores key-down position against the stable fullscreen frame. Missing/outside coordinates or a viewport/effective-scale change during a hold are a no-op. `$cursor` itself is a fixed snapshot in the reviewed native source, not a moving anchor. No untrusted hold-time classifier is added.

Automatic selection prefers inactive configured markers, then wraps/reuses the configured order when every configured marker is active. Custom order and world-marker IDs remain distinct from icon artwork IDs. A selected sector inside the order can guide the next local choice; a sector outside it does not reorder saved preferences. Empty order is a center no-op while the eight sectors remain available. Clear requests reset the local cycle; the client still decides whether clearing or placement succeeds.

Fresh activity resync happens only when the tool is enabled and combat is known false, before an eligible new key-down and on bounded native activity/context events. All eight `IsRaidMarkerActive` results must be ordinary booleans before any protected activity attributes change. Missing, throwing, malformed or secret data preserves the previous snapshot. No activity query or insecure protected-state write occurs in combat/unknown state. Existing active Diamond is skipped regardless of who placed it. An active result does not establish ownership or acknowledgment of our request.

The restricted environment does not export active-marker queries. Combat/unreadable mode therefore combines the last readable snapshot with local issued choices/reservations. **A pending or cancelled native reticle may remain reserved until the next safe readable resync.** This is bounded local history, not complete live group occupancy or confirmed placement. Outside combat, a fresh inactive result discards a cancelled/failed pending sector; an active result can move the sequence to the following configured position. No generic spell-change event is treated as a placement ACK. No polling, retries, cursor movement, synthetic input or insecure placement call is added.

Restricted reset clears held state, origins, macro, catcher, transient bindings and visual work before the protected action. Cancel-before-arm, repeated up/down, stale visual callbacks, profile/input suppression and context hides remain guarded. The original native reticle cancellation path is retained. At most one local diagnostic replaces the last owned action: `/dump RCPArsenal.WorldMarkers:GetLastAction()` shows branch, marker, sequence position and exact macro (or an explicit no-op). This performs no placement or network send.
