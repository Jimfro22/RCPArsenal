# Marker key and click wheel (alpha.25)

The optional wheel uses the owner's explicit-click choice. Press the marker key to show the clickable wheel immediately. Without clicking an icon, release requests the next configured marker at the current cursor regardless of pointer travel or hold duration. The wheel can briefly flash on a tap. There is no protected elapsed-time gate or invisible delayed hitbox.

To choose a specific marker, hold the key and complete a left click on its visible icon, then perform a separate real ground click. Its icon macro is `/wm N`; automatic release uses `/wm [@cursor] N`. The icon action runs on the completed click, and a restricted post-handler then hides the wheel. Releasing the marker key after selection does not place another marker. If key release interrupts an unfinished icon press, the gesture cancels rather than placing automatically. Right-click/Escape cancels before selection and native targeting afterward. Wheel OFF retains down-phase instant cursor placement.

Alpha.24 widened the geometry boundary to address small jitter. Native testing showed larger pointer movement still produced reticles, so that was not the requested timed tap/hold fix. Alpha.25 removes pointer-angle authority from key release. Ordinary timers, animation callbacks and an offscreen auto-hide sentinel cannot supply a validated protected combat clock in the reviewed source; no such mechanism is introduced.

The existing Place/Clear binding commands and saved key choices remain unchanged. The initial native CLICK command does not reveal its source key, so an independent protected router is configured only outside combat to tag each saved chord with its physical base key. Temporary secure routes retain that tag through all modifier combinations. A consumed or cancelled gesture drains only on its owner's key-up; unrelated bound keys cannot drain it. Repeated downs cannot reopen a consumed gesture. Release routes also drain ignored secondary holds before clearing. No ordinary code changes protected bindings or action decisions in combat.

All eight protected buttons have their actual artwork under the same secure parent that controls their visibility. There are no timer-created controls, protected changes from OnUpdate, or moving invisible overlays. Their initial layout uses the secure cursor snapshot. A changed viewport/scale rejects stale icon clicks. Key release does not sample pointer coordinates. Input suppression, blocked contexts, Clear, profile/configuration changes and native hide cleanup remain guarded.

Automatic selection retains alpha.24's inactive-first configured sequence, custom order, local issued history and wrap/reuse when all configured markers are active. Empty order makes an unconsumed release a no-op while icons still offer all eight markers. Clear resets local selection history; the engine decides whether requests succeed. A manual icon inside the configured order can guide the next local choice without changing saved order.

Activity is resynchronized only while enabled and combat is known false, before eligible new input and on bounded native events. All eight IsRaidMarkerActive results must be ordinary booleans before protected snapshot attributes change. Missing, throwing, malformed or secret results preserve the last snapshot. Combat/unreadable state uses that snapshot plus local issued reservations. A cancelled or unfinished native reticle can remain reserved until safe readable resync. An issued macro, armed reticle or generic spell event is not placement acknowledgment.

`/dump RCPArsenal.WorldMarkers:GetLastAction()` shows only the latest owned branch, marker, sequence position and macro/no-op. It sends no network message and performs no placement.

Confirm no selection click becomes a terrain click and no second marker follows key release. Check both saved bindings independently, another binding released during a hold, modifier changes, repeats, side buttons, native action-keydown CVar settings, cancellation before/after arming, Clear and context changes. Check visible artwork/hitboxes, UI scale, mouselook and existing UI under the pointer.
