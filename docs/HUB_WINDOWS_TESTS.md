# Historical 0.15.0-alpha.1 Windows validation

For current navigation, defaults and the alpha.22 combat acceptance owner test, use [Windows smoke test](WINDOWS_SMOKE_TEST.md) and [General and Personal Tools](SETTINGS_CLEANUP.md). The historical steps below retain their original build context.

All checks below remain pending until run in the actual WoW client. Record exact client build, TOC/addon version, ZIP SHA-256, profile schema, install path, roster roles, external addon versions, and Lua errors. Keep a SavedVariables backup; preserve the baseline and prior marker alpha installers.

1. **Fresh quiet login:** with a fresh profile, fully quit/restart WoW. No hub popup, HUD, puck, PANIC, reminder, demo, automatic talent inspection, or group query. `/rcp` opens Addons. Visiting every pane and using position reset keeps switches off.
2. **One-time migration:** separately use a schema-17/18 test backup. Confirm old overlays/scans/actions become off once; content, positions, appearance, and templates survive. Schema-18 marker enable/order survives. Explicitly opt in, restart, and verify schema-19 choices persist.
3. **Cold enabled profile (original icon regression):** deliberately enable both HUD and puck, save/logout, completely quit/restart WoW, then log in WITHOUT `/reload`. Check PANIC glyph, logo, Sort, Odd/Even labels, missing-provider label, and each flyout spell icon immediately and after six seconds. Repeat a cold start and only then compare `/reload`. A fresh off-profile followed by late enabling is a different test and cannot close this regression.
4. **Puck-only cold startup:** HUD/scans off; puck on. Restart into a raid. Verify no talent/NotifyInspect work; open/pin dock, disable puck, leave raid, reset profile. Dock, flyouts, badge, and mouse monitor must close. Ready check/countdown must not silently enable scans. Unknown-spec sort explains the dependency.
5. **HUD consent/visibility:** enable HUD/scans explicitly and observe the queue; disable and verify timers/late inspect replies cannot resume it. Repeated refresh while hidden solo/leader-only must never show PANIC alone. Preview/recenter/import do not opt in. Secure content remains a pre-pull snapshot in combat.
6. **Command routing/collision:** `/rcp` always returns to Addons even after an advanced pane. Try tools/raid/settings/markers and legacy aliases. With a real conflicting `/rcp` addon, Arsenal does not steal its hash; `/rcparsenal` opens the hub and Settings reports the conflict.
7. **Local metadata:** test installed/enabled/loaded separately, disabled-pending-reload Arsenal, load-on-demand BigWigs, missing addons, no Version, placeholder builds, and full long versions. Link modal is reusable, blocks background clicks, and disappears on close/navigation.
8. **Targets:** capture from enabled addons; missing/disabled/unknown does not erase prior target. Edit/clear one target, relog, import another profile, and verify local targets persist. Reset Profile has Cancel/Reset and describes effects. No automatic web latest-version claim or remote target write.
9. **Two-client group query:** leader/assist queries a current Arsenal client with all optional tools off. Check all seven rows, Arsenal protocol/build, same-realm sender format and cross-realm identities. Ordinary members cannot query. Missing is explicit; an addon with known old version but unloaded still shows its version comparison alongside load state.
10. **Transport failures:** no Arsenal/old protocol, partial response, offline, timeout, duplicate/replayed/unsolicited/oversized/malformed input, outsider, new same-name/different GUID, repeated queries/cooldown, leadership change, combat during queued response, and group replacement during combat. Unknown/offline never becomes missing/current. Old snapshots age visibly while pane stays open. No UI-only timer sends queries.
11. **Normal resurrection:** off produces no acceptance. Opt in; test ordinary offer, recovery delay, canceled/duplicate offer, dead player with pet still fighting, party/raid member or pet combat, active encounter, uncertain APIs, combat starting during deferral, ghost state, relog. Combat/encounter offers remain manual. Record whether the native client accepted the request; source cannot prove spell-type classification.
12. **Reminder placement/off behavior:** Preview/Move/Stop/Reset with checkbox off must show only a labeled sample and keep switch off. Drag and reopen/relog to confirm position persists. Close/navigate/combat ends sample. Disabled live tool runs no health/item polling or frames until explicit preview.
13. **Native threshold and item readiness:** use safe test conditions to check health just above, equal to, and below the threshold, including 1%/99%; native Step equality is unverified. Check real health recovery, absent/restricted/secret cooldown values, Healthstone priority, both stone IDs, known potion qualities, shared cooldown/charges, bag updates, item consumption, death/ghost, zoning, and combat transitions. Unavailable/unknown item data must show nothing. Bounce is visual only; use your own keypress. No AutoPotion dependency.
14. **Screen and interaction:** verify 1280×820 layout and smaller UIParent resolutions/scales, wrapping, category select versus checkbox, content toolbar, advanced Back links, profiles, nonoverlapping Quick Bar switches, and normal/optional catalog labels.
15. **Regression:** run WORLD_MARKER_TESTS.md for secure marker hardware/permissions/terrain/raid combat; test existing sort/split/undo, changed-side whispers, local/external countdown start/cancel, positions, import/export, and taint logs with the team's actual addon set.

Do not mark these tests passed based on the offline harness. Conditional reminder/normal-res code in this alpha is not a claim of completed native feasibility. NSRT adapter/note workflows, announcement timing/receiver, WowUtils Bridge ownership, and CurseForge moderation/installability remain separate work.
