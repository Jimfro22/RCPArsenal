# Navigation, direct marker keys and reminder polish - 0.15.3-alpha.6

Historical glow detail: [alpha.11 icon glow](ICON_GLOW.md) extends the existing effect to visible potion icons and adds the Personal Tools switch; it supersedes the Healthstone-only description below.

Bare /rcp, /rcp config and generic window-open buttons restore the last valid view, including Available Cooldowns subtabs. Explicit destinations such as /rcp addons, /rcp markers and /rcp tools retain priority. First use or invalid/removed saved views fall back to Addons & Versions. Navigation is stored in RaidArsenalDB.navigation outside portable/resettable profiles; import, reset, close and reload do not discard it or activate tools.

## Edit marker keys inside Arsenal

World Markers retains its existing order and secure place/clear actions. The Key Bindings card now shows two clickable native key slots per action, a separate Unbind control for each, the current Account/Character scope and a secondary WoW keybinds button. Assigning a key never invokes a marker action, enables the cycler or changes its secure attributes/sequence. Existing native assignments remain outside Arsenal profiles.

Click a slot, press a keyboard key or middle/extra mouse button with any modifiers, then release it. Pure modifiers, unknown keys and left/right mouse buttons do not bind. The chord is recorded on press and committed only after the matching release. A conflicting persistent command gets a concrete Replace / Cancel prompt; no overwrite occurs before confirmation. Commit rechecks the target keys, optional action context, conflict, active binding scope and definitely out-of-combat state. The untouched key and unrelated assignments remain. Unbinding the primary may promote the remaining alternate in Blizzard's native list. Existing wheel/gamepad bindings remain usable and may be edited with the WoW keybinds fallback; this compact editor consumes wheel input without assigning it.

Only the two fixed existing CLICK commands can be assigned. SetBinding's third argument is the optional action context, not Account/Character scope. SaveBindings uses the captured/revalidated current set (1 Account, 2 Character); nil is its normal no-return result. Public exact-true write results and mapping readback are required. Partial failures attempt a bounded restore of only touched mappings while still out of combat. Failed/blocked rollback is reported as unconfirmed. There is no LoadBindings reset, scope switch, override binding, action invocation or CVar write.

Escape, Cancel, tab/window hide, combat entry, external binding changes and profile reset/import invalidate the edit without writes. A held gesture keeps a separate release-only drain, so its up event cannot commit a cancelled assignment or escape to a release-based action. The ordinary UIParent-owned input frame is preflighted as publicly unprotected and configured outside combat; it is already shown before any combat cancellation. No restricted keyboard/propagation reconfiguration occurs on the combat drain path. A visible cue says to release the key, or tap it again if a focus transition lost its up event. Other input is briefly consumed until that matching release. There is no timeout that silently drops held-release ownership and no deferred save after combat. Native hardware dispatch, mouse-up away from the old window rectangle, focus recovery, permission and taint still require client acceptance.

## Reminder defaults, glow and mute policy

Fresh/missing or invalid sound preferences resolve to Sound 6 and Master. Valid saved choices (including SFX/built-in alert) and sound OFF remain unchanged. Prior automatically filled defaults are indistinguishable from intentional choices, so they are preserved too. The six supplied Ogg files and provenance are unchanged.

A selected Healthstone prompt gains a steady warm-gold two-unit border plus restrained four-unit outer halo at or below 35%, clearing above 35%. Its fixed cached curve is independent of the configurable main threshold. The owned glow is parented under the existing moving reminder body and main native health/visibility gate. On health events the opaque output goes directly to glowFrame:SetAlpha(UnitHealthPercent("player", true, glowCurve35)); there is no Lua health comparison, alpha readback or audio trigger. Only public selection/policy/life state gates or resets it. Potion/empty/unknown/disabled/dead states clear it. Glow creation/curve/sink failure suppresses only glow; a successful main reminder, selection and cooldown-expiry timer remain intact. Bounds include halo and bounce without changing the saved anchor. The expected native precision boundary remains an explicit acceptance limit.

The compact Play when game effects are muted option defaults OFF. With Master selected, a definitely public Sound_EnableSFX=false blocks a playback request unless this option is ON. ON permits the already-selected Master route; it never changes the route or game CVars. With SFX selected the control is inactive and its saved value is retained; normal SFX mute still applies. Global Sound_EnableAllSound=false and zero Master volume block both routes regardless. Unknown/secret/error state is not asserted as a known mute. Selection/policy edits remain silent, do not rearm/retry a consumed native warning, and do not query health/bags. Both explicit Preview and automatic playback use the same guarded policy. This option does not promise playback through global, OS/device or background sound suppression.
