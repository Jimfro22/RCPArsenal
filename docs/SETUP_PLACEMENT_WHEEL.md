## Optional marker wheel

Fresh `worldMarkers.radialEnabled` is false. The existing Place/clear CLICK names and saved keys stay stable. The World Markers pane edits the requested option with `SetRadialEnabled`, reports effective fallback and retains normal sequence editing. Clear all stays separate. No MarkerBindings or Bindings.xml action is replaced. Editor capture/release-drain and global placement have independent input-suppression owners so one close cannot clear another's guard.

With effective wheel mode enabled, nothing places on down. Every center/no-sector release cancels without placing, including a quick tap or stationary long hold. Hold and aim chooses one of eight stable world-marker sectors; release resets the wheel and issues `/wm N` to open Blizzard’s normal ground-targeting reticle. Then left-click the ground to place, or use native right-click/Escape to cancel targeting. The normal non-wheel sequence retains instant `/wm [@cursor] N`. Escape/right-click cancels across the game viewport, including held modifiers, through a protected right-click catcher and transient bindings. Other mouse buttons pass through. See the [cancellation and targeting contract](RADIAL_CANCELLATION.md). The 0.18-second presentation delay only suppresses visual flash; elapsed time never classifies a protected action. Release mouse look before aiming. Blizzard checks permissions, ground targeting and valid terrain.

If any Place alias is a primary mouse button, Escape or a wheel/pulse input, the whole Place action falls back to the normal sequence: the native CLICK does not identify which physical alias caused it. The requested wheel preference remains saved; compatible keys restore the mode. Modifier-first release uses owned transient secure bindings, without SetBinding/SaveBindings changes. Both simultaneously held Place aliases cannot be distinguished; the first routed release ends the gesture. Standard one-held-binding use is the prototype target.

Only the unprotected presentation uses a cancellable timer and bounded visible OnUpdate, at most10seconds. A genuinely lost key-up leaves a static “Release the marker key or press Escape” recovery cue; no polling continues and no insecure combat reset is attempted. A real release, Escape/right-click, supported native context/UI hide or safe reconfiguration ends the hold. No idle wheel timer/OnUpdate runs when OFF. Source proof and offline snippets do not establish native hardware, taint or combat success.
