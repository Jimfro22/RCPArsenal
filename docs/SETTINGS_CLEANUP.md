# General and Personal Tools — alpha.23

General applies changes immediately. Its Personal tools column contains Auto resurrection and Consumable reminder; Raid tools contains Quick Bar and Available Cooldowns. Each has a separate Settings action that only opens its owning page. Both columns remain visible for either saved presentation role. Changing a master preserves child preferences. Quick Bar OFF → ON retains its existing provider-coverage activation default; refreshing an already enabled bar preserves a later coverage OFF choice. Available Cooldowns enables its HUD and inspection, with static provider ownership rather than cooldown-use or remaining-time tracking. Hover help states those limits. Rejected changes show a local reason and never apply later automatically.

The staged Setup editor, Review choices, Save choices, Resume review, draft/profile-conflict lifecycle, and hidden SETUP pane are retired. `/rcp setup`, `OpenSetup`, and saved or explicit SETUP routes open General. Existing saved presentation roles remain untouched. A fresh neutral `/rcp` visit starts on General once, without opening the hub at login; subsequent neutral visits restore the last ordinary page and Available Cooldowns subtab. Preview All and Move All remain in the bottom-left shelf, with existing placement behavior and samples. General remains first and Personal Tools second in the persistent navigation; Obsidian Ember styling remains.

All six external Morning Brew addons are always visible in compact alternating rows: Northern Sky Raid Tools, RCLootCouncil, Simulationcraft, WowUtils, AutoPotion and BigWigs. Each row shows a clickable name, Important/Optional display priority, and right-aligned local state. Core and Team tool catalog priorities display as Important here without changing catalog data. Installed and enabled names/statuses use the Arsenal accent; missing, disabled and uncertain entries are gray. Not loaded, disabled with reload required, missing and unknown remain distinct labels. Every name opens its CurseForge copy-link dialog regardless of installation state. No row enables another addon, claims configuration/latest version, or initiates a group query.

Personal Tools has two main sections. Auto resurrection has the indented dependent Also accept during combat switch. Consumable reminder exposes Visual health threshold and Show reminder when enabled; an OFF reminder still offers Settings without opting in. Sound, Appearance, Messages and Item behavior start closed, with one open at a time. Appearance contains Glow at 35% or lower and nested Advanced glow. Warning sound (35%) and glow remain separate from the editable visual threshold. Requires Master stays visible on the muted-effects permission when needed. Routine off/combat-visibility prose is removed; actual manual-offer and unavailable/unknown reminder reasons remain visible. Captions, sizes, choices, ranges, readiness policy, audio latch and glow rendering are retained. One native scroll body grows for expanded controls and clamps when folded. Owned menus/pickers close on scrolling, collapse, navigation, context exit and profile replacement.

Both resurrection preferences default OFF. The child is a strict boolean when migrated and is disabled in the UI without the parent; a saved checked child has no effect alone. With the child OFF, player lockdown, encounter, local pet, party/raid member or pet combat, and unreadable combat state leave offers manual. Child ON bypasses that combat-classification scan for future incoming offers; it does not identify a battle-res spell or cast anything. The visible decision line says: “Accept offers during pulls and boss fights. Does not cast resurrection.” Hover help explains immediate acceptance and client rejection.

Each RESURRECT_REQUEST invalidates the previous request and may schedule one zero-delay callback. Generation ownership is checked before any stale callback writes. Changes to either switch, parent shutdown, reset/import/profile replacement cancel the timer and invalidate its generation; no setting handler, UI refresh or combat-end event replays an offer. Resurrection-only edits preserve reminder inventory, readiness timers, visual state and audio state. The deferred call rechecks the valid ordinary offerer, dead/ghost state, game-rule namespace and required APIs. An existing Hardcore predicate must return an ordinary false value; true, unreadable or non-callable predicates stay manual. Mainline may omit that optional predicate: omission is allowed only with a valid namespace and positively identified Retail project constants. Missing/malformed namespaces stay manual; an omitted predicate with unknown/unsupported flavor identity also stays manual. This is no broader Classic compatibility claim. Sickness selects the timed branch first; otherwise a readable timer flag selects it. Only timed/sickness offers require a finite zero corpse recovery delay; no-timer offers do not query that unrelated delay. Unknown/secret/throwing data stays manual. One direct AcceptResurrect request is permitted, with no retry, popup click or forced dismissal. A non-throwing call is labelled request only, not confirmed resurrection; native manual popups remain recoverable.

Offline actual-module harnesses verify state, routes, addon links/colors, default/child persistence, request races, timer selection and controlled layout bounds. They do not establish native visual fit, taint behavior, acceptance by the client/server, or spell classification. Use the current checklist in [Windows smoke test](WINDOWS_SMOKE_TEST.md). Native owner acceptance remains open. The owner authorized GitHub and CurseForge delivery of alpha.23; successful upload and CurseForge approval must be checked separately.
