## Local reminder

Carried Healthstone first, then a supported carried healing potion. No cooldown/usability test and no automatic item or macro action. The local snapshot enumerates only backpack and five equipped bag indices (0–5), never banks. Healthstone presence uses an ordinary positive stack count, not remaining uses/charges. Missing/secret counts or item data are unknown, not zero. Missing icon metadata does not erase a known item; a built-in illustration provides its display fallback.

Confirmed absence of both item kinds selects **OUT OF POTIONS**, with no item icon or background. The warning shares the native health alpha sink and remains while low and empty; recovery/replenishment clears that condition. Unknown/unclassified potion data suppresses a definitive empty warning. There is no five-second one-shot, sound, health-entry latch, alpha/visibility readback or animation-derived health event.

The reminder uses native predicted health, matching the default used by Blizzard health bars; it does not reconstruct prediction in Lua. The live health result is used only as `SetAlpha(UnitHealthPercent("player", true, curve))`. Native Step curves use the normalized 0–1 domain. Inclusive public threshold points place the zero point one expected binary32 precision step above the boundary, then validate stored ordinary points and interpolation using constants. Binary32 input precision is an implementation assumption, not proven by the public point self-test. This creates a tiny precision interval above the requested boundary; native threshold/render/taint acceptance remains required. The bounce is a constant child translation; public `IsPlaying()` repairs a stopped animation independently of health.

Settings provide Both / In combat / Out of combat, separate 24–128 icon and 8–32 text sizes, and independent literal Healthstone/potion messages (60 characters, blank hides text). New icon size is 56; unset text size retains the previous native font template height. Resizing preserves the saved icon anchor. Messages and icon bounce together. Preview offers an explicitly selected sample, independent of inventory/health/opt-in; Move keeps it still and saves only a real drag. Reset position changes only the anchor. Text uses the existing font/caption system and escapes markup; edit drafts stay outside caption replay.

Inventory refresh is event-driven while opted in, with no readiness ticker. Health events never scan bags. Bag events invalidate before visibility/death guards; hidden modes scan once when eligible again. Item-data events only reconcile a genuinely pending bag item; a cached unrecognized spell is not pending, without requesting any data. Disabled reminders do no inventory work. Editing appearance reuses the current inventory snapshot.

## Explicit raid check and finite cost

Personal Tools → Check Raid Supplies is separate from Addons & Versions. Raid lead/assist only, outside combat/encounters/client restrictions. One explicit request on a dedicated prefix, one local bags snapshot per participating client, one tiny whisper response per client, no retries. View Results only renders stored reports. No talent inspection, remote inventory API, background/periodic bag polling, data loads, health reads or readiness claim. Participating Arsenal clients report their own bags; older clients/no response remain unknown.

Each bags evaluation has six bag-size calls and at most 600 slot-ID visits (100 per bag cap); occupied supported slots read info once. Classification is deduplicated by item ID within the snapshot. Unmapped items use cached metadata only. Oversized/unreadable bags remain unknown. This is finite work, not zero overhead or a measured native FPS guarantee.

Protocol 1 / map revision 1: `Q|1|nonce|1`; `R|1|nonce|1|stone|potion`, flags `1/0/u`. Packets cap at 100 bytes. Each initiator waits 20 seconds between explicit checks; response window is 12 seconds with at most one timer. Each responder evaluates/replies at most once globally per 20 seconds, including failed sends; eight recent nonces per current roster identity prevent replay. At most eight incoming query identity walks per 20 seconds. Active-response validation admits only a pending member from the frozen request, then checks the current roster/name/GUID/fingerprint. Duplicates and outsiders cannot cause repeated native roster walks. Roster/world/combat/restriction changes cancel the window and mark results stale. No wire value chooses a unit token or asserts another player's identity.

Rows distinguish Carried, None carried, Unknown, No reply and Offline. Summary labels count players, not items. Report age is sampled only when rendered; no age ticker queries bags or sends requests. Counts/positive reports describe carriage, not cooldown readiness. All results can become stale immediately after a bag change.
