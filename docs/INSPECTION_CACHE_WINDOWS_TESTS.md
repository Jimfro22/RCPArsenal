# Inspection cache acceptance — 0.15.2-alpha.1

These native WoW tests are pending. Offline lifecycle tests establish addon decisions, not game event ordering, persistence to disk, inspection interoperability, rendering, or taint. Preserve SavedVariables backups and the verified earlier installers.

Install the versioned RCPArsenal ZIP with WoW closed. Record WoW build, Arsenal version/build, ZIP checksum, character/realm, HUD and puck choices, tracked groups, and the confirmation/cached/unknown counts. Existing 0.15.1 installs never saved inspection reports; the first successful inspection in this build seeds the cache.

1. **Seed and reload:** explicitly enable Capability HUD + talent inspection, join the test group, and finish one successful scan. Record providers/specs and `/rcp status`. `/reload` with the same roster and settings. The useful HUD should reconstruct promptly with C markers and cached counts; successful cached members must not enter a blanket inspection queue. Let login/world/roster/ready-check events settle and wait beyond the missing-retry delay. Record any inspection requests separately from unrelated addon traffic.
2. **Cold login:** fully quit WoW, restart, and log into the same character/roster without `/reload`. Confirm restored providers and their original age. Repeat enabled HUD and puck-only cold-login asset checks; neither restored data nor an unknown startup API value should trigger a full scan.
3. **Off and puck-only:** disable HUD + inspection, leave the independent puck enabled, and reload/login. No remote inspection requests or local talent collection may run. Open `/rcp` and change unrelated settings. Enabling HUD later should restore matching saved facts before checking genuinely missing members.
4. **Identity:** test same-name players on different realms, a replaced GUID under a known name, changing raid unit tokens, leave/rejoin, and bench/tracked-group transitions. Only exact GUID plus qualified name and class matches may restore. No old member's capabilities may transfer to a replacement.
5. **Unknown startup facts:** at a real loading transition, unknown class, NONE/unassigned role, or unavailable/zero spec must not look like a definite change. Useful saved data should remain marked cached. A genuinely different known class/role/spec should invalidate only the affected member and allow an ordinary targeted inspection outside restrictions.
6. **Actual changes:** have one member change spec and talents. Confirm positive detected changes target that member while unaffected saved members remain. Unobserved remote talent changes can remain unknown to Arsenal: cached tooltips must never promise live talents. `/rcp rescan` deliberately confirms the tracked roster again.
7. **Manual controls and failures:** `/rcp scan` fills holes; `/rcp rescan` or Full Rescan deliberately re-inspects required tracked members. Pause/resume still works. Failed/out-of-range/manual refresh must not relabel historical data as newly confirmed. `/rcp clearcache` explicitly forgets saved inspections and begins a new allowed scan. Off/combat guards still apply.
8. **Restrictions and late replies:** trigger combat/encounter transitions, spec changes and roster replacement during an inspect request; turn inspection off with a reply pending. Late/irrelevant replies must not adopt a wrong GUID or revive invalidated evidence. Resume only genuinely required work after restrictions end. Inspect-frame ownership and native late-event correlation still need real-client observation: INSPECT_READY carries a GUID, not a request token, so a delayed response for that same GUID after a newer request cannot be universally correlated offline.
9. **Storage and export:** after a clean logout, inspect a backup copy of SavedVariables. The cache is local metadata outside `profile`, contains finite confirmed facts and timestamps, and contains no frames or unit tokens. Export/import an appearance profile; no other players' cache should travel with it. Corrupt/incompatible/expired entries in controlled backup fixtures should be rejected without resetting schema19 choices, positions, markers, NSRT or personal tools.
10. **Honest display and existing tools:** compare compact C markers, detailed [C] owners, cached-age tooltips, scan/settings counts and `/rcp status`. Queue progress and reusable data must not imply live readiness. Existing sorting/splitting must reuse compatible saved specs without a reload-only full-rescan requirement, while showing the saved-spec notice. A changed GUID/name/class/known role, incompatible or expired record, or genuinely unknown spec must not be guessed. Keep foundation/NSRT/marker regression checks separate.

The saved-cache retention policy is 160 entries and 30 days, measured from the original successful observation. A normal reload does not renew a timestamp or expire otherwise usable entries solely to force inspection. Changes made while Arsenal cannot observe them remain a documented reason to refresh manually.
